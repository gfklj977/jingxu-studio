# 镜序工坊功能实现可行性体检

体检日期：2026-09-03  
结论口径：`通过`表示已经执行真实测试；`技术链通过`表示关键底层能力已验证，但产品功能尚未完成；`待联调`表示需要账号、密钥或目标平台环境；`待平台验证`表示必须在对应操作系统实机执行。

## 一、结论

- 当前已经开发的工作台功能：通过。
- 本地数据库、1080P 视频编码、音频编码和浏览器控制：技术链通过。
- 文本生成、搜索、生图、TTS、ASR：接口架构可实现，但当前没有用户密钥，不能声称真实服务调用通过。
- 抖音、小红书、视频号投稿：浏览器自动化基础能力通过；登录、页面适配、自动填写和人工发布交接仍需各平台测试账号联调。
- macOS Apple Silicon：当前机器满足开发与验证条件。
- Windows 10/11：设计可实现，但必须在 Windows x64 实机或 CI Runner 上完成安装包和浏览器回归，不能用 macOS 测试结果替代。

因此，现阶段可以确认“方案没有发现不可实现项”，但不能确认“所有产品功能已经测试通过”。完整通过必须以功能开发完成、配置服务密钥和准备平台测试账号为前提。

## 四、本机条件与阻塞项

- 当前设备：Apple Silicon arm64、16GB 内存、10 逻辑核心、可用磁盘约 304.6GB。
- SQLite 可直接使用。
- 原应用内含可用 FFmpeg/FFprobe；新产品必须独立合法打包自己的媒体二进制，不能依赖原应用安装路径。
- 系统当前没有 Rust/Cargo，因此若最终采用 Tauri，需要安装 Rust 工具链；也可评估 Electron 以减少本机前置依赖。
- 系统 Python 当前缺少 FastAPI、Uvicorn、Pydantic、pytest；应在项目虚拟环境中锁定安装，不能污染系统 Python。
- DeepSeek、豆包、Tavily、方舟、API易、胜算云密钥当前均未配置。

## 五、放行标准

只有同时满足以下条件，才能宣布“所有首版功能均已测试通过”：

1. 每个矩阵条目至少有一条自动化测试或可复现人工验收记录。
2. 使用 Fake Provider 完成无费用的全流程黄金项目。
3. 使用真实 Provider 各完成一次脚本、搜索、生图、TTS、ASR 联调。
4. 使用三个参考成片完成画质、字幕、转场和音量校准。
5. 三个平台分别完成“自动填写至发布前一步”的隔离账号测试。
6. macOS 和 Windows 安装包均通过干净机器测试。
7. 断网、限流、任务取消、进程重启、磁盘不足和素材损坏场景通过。
